# 英文小游戏本土化工作流

以原版英文作为对照，把移植好的 H5 游戏调整为简体中文。每款游戏保留自己的运行方式和语言资源，大厅只负责展示中文目录和打开游戏。

## 1. 记录原版，再跑通 H5

- 在原版记录开始、教程、局内、暂停、结算和重玩等实际存在的状态。保留原英文文案和截图，方便核对语境与玩法。
- 仅有安卓原生版时，先移植到 Web。处理依赖 Activity、Android 原生输入或存储的部分，确认 H5 能从独立入口完成一局。已有可玩的 H5 版本时，可直接进入文案整理。
- 将 H5 成品放在 `games/<id>/`。资源使用相对路径，确保在站点子路径上也能运行。

## 2. 把玩家能看到的英文整理成语言资源

- 优先复用游戏原有的本地化系统。没有现成系统的轻量 H5，可参照[星轨疾行的语言包](../games/star-dash/locales/)建立 UTF-8 的 `en.json` 和 `zh-CN.json`，用稳定的键引用完整句子。
- 沿玩法走一遍再搜代码。覆盖菜单、按钮、教程、局内 HUD、暂停与结算，以及加载失败、解锁、提示、无障碍标签和浏览器标题。检查 DOM 之外的 Canvas 文本、贴图文字和字幕。
- 给短词记录场景。比如 `Retry` 在结算页可以译成「再玩一次」，在加载失败提示里则用「重试」。同一个道具、资源或操作在所有页面用同一个中文名称。

## 3. 翻译并接入中文

- 按玩家完成操作需要知道的信息翻译。键盘与触屏提示对应 H5 版本的实际操作，数值和玩法规则沿用原版。
- 保留 `{seconds}` 等动态变量的名称和次数。按中文语序调整它们的位置，把数字、单位和标点放在同一条文案里交给语言包处理。使用 UTF-8，确认游戏字体和纹理图集包含要显示的中文字符。
- 将默认语言设为 `zh-CN`，同步设置文档的 `lang` 和标题。对照验收可保留原版语言入口，样例使用 `?lang=en`。大厅读取的中文标题、简介与分类在 [`catalog.js`](../catalog.js) 维护。

样例把同一个飞行时长占位符用于两种语言，运行时再填入实际数字。

```json
{ "flightTime": "Flight time: {seconds} s" }
```

```json
{ "flightTime": "飞行时间 {seconds} 秒" }
```

## 4. 检查后再收录

使用上述平铺 JSON 格式时，在仓库根目录运行以下命令。把参数换成待收录游戏的语言包目录。脚本对比两种语言的键名、非空文案和 `{name}` 或 `{0}` 形式的占位符。使用引擎自带语言表的游戏可用该引擎的校验流程。

```sh
node scripts/check-locales.mjs games/star-dash/locales
```

- 从大厅点进游戏，确认默认加载中文、正常开局、能结算和重玩，并能回到大厅。
- 用窄屏手机尺寸和桌面尺寸各走一遍，检查缺字、截断、重叠和触控提示。出现数字的文案用较大数值确认显示完整。
- 对照原文和实际画面，检查漏译、术语前后一致性、图片中的英文，以及调试时容易跳过的错误和空状态。
